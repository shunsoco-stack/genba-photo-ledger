# 工事・現場写真台帳

## 概要

小さな工務店・設備工事会社の現場担当向けに、工事写真を整理して提出用の写真帳を作るブラウザアプリです。日本語UIで、スマートフォンでは下部タブ、デスクトップではサイドバーから操作できます。写真・工事情報は利用中のブラウザに保存します。

## 主な機能

- **写真の整理**：現場の登録、工種・場所・撮影日・区分での絞り込み、工種／日付／場所ごとのグループ表示、撮影日時順の表示、写真帳への掲載選択。写真追加時に長辺1600px以内へ縮小し、JPEGに圧縮します。
- **黒板風の情報**：工事名・工種・場所・測点・撮影日・施工者を緑色の黒板に表示。四隅の位置と3段階のサイズを選び、黒板入りJPEGを保存します。元画像は保持します。
- **写真帳の印刷・PDF保存**：表紙付き、A4縦、1ページ3枚。写真の右に撮影情報・メモを掲載し、ページ番号を付けます。印刷ダイアログでPDF保存先を選択できます。
- BOM付きCSVの保存（現在の絞り込み結果）、画像をbase64で含むJSONバックアップの保存・検証・復元、既定データの再生成。

## 日時の扱い

日付は `YYYY-MM-DD`、時刻は `HH:MM` の日本時間です。「今日」はクライアントのマウント後に決めます。初回起動・既定データへのリセット時に、その時点の日本時間から相対的に撮影日と工期を生成します。保存済みの記録は、起動のたびには変更しません。

サンプルの撮影はすべて生成時点より前、8:00〜17:30の範囲です。撮影は前営業日までとし、土日・日本の祝日（振替休日・国民の休日を含む）・12/29〜1/3・12時台を避けます。工事の進み具合に合わせて着工前・施工中・完了の順に並びます。0時台でも未来の撮影は生じません。工期の終了日は進行中の現場では未来です。

追加した写真の既定の撮影日時にはファイルの `lastModified` を使用します。EXIFは読みません。編集画面で変更できます。

## 既存作品との違い

| 作品                             | 主な目的                   | この作品との違い                                                 |
| -------------------------------- | -------------------------- | ---------------------------------------------------------------- |
| 納品・検収チェック               | 納品物の検品・検収記録     | 検品や検収サインを扱わず、工事写真の整理と写真帳出力に特化       |
| 現場トラブル受付・修理進捗ボード | 問い合わせと修理対応の管理 | トラブル受付や修理進捗は扱わず、施工の状態を写真で記録           |
| 画像一括リサイズ・圧縮ツール     | 画像のサイズと容量の調整   | 縮小は取り込み時の補助機能。現場・工種・黒板・写真帳を中心に構成 |

日報・巡回ルート、工程表、原価・見積管理は対象外です。

## 画面一覧

| パス                              | 画面                                                 |
| --------------------------------- | ---------------------------------------------------- |
| `/`                               | 工事一覧・工事登録・写真枚数・最終撮影日・未整理枚数 |
| `/projects/[id]`                  | 写真一覧・絞り込み・グループ切替・追加・CSV          |
| `/projects/[id]/photos/[photoId]` | 写真情報・黒板の編集・JPEG保存・前後の写真           |
| `/projects/[id]/album`            | 表紙付き写真帳プレビュー・印刷                       |
| `/projects/[id]/settings`         | 工事情報・工種・場所の編集                           |
| `/backup`                         | JSONバックアップ・復元                               |
| `/about`                          | 保存方式・使い方・既定データへのリセット             |

IDはクライアント側でURLから読み取ります。追加した工事・写真のIDにも対応します。標準の `next build` と `next start` では直接アクセス・再読み込みが可能です。

静的書き出しする場合は `next.config.ts` に `output: "export"` を追加してビルドします（`turbopack.root` は保持）。任意IDの直接アクセスには、静的ホスト側で `/projects/*` を `/index.html` にフォールバックする設定が必要です。アプリ内のリンクはHistory APIで遷移します。静的ホストの404ページに生成された `404.html` を使う場合もクライアント側で記録を表示できますが、HTTPステータスは404となるため、200で返すフォールバックを推奨します。

## データの保存先

| 保存先                            | 内容                                                         |
| --------------------------------- | ------------------------------------------------------------ |
| localStorage `cpl:v1`             | 工事情報・写真の属性・掲載選択・黒板設定                     |
| IndexedDB `cpl-photos` / `images` | JPEG画像。localStorageには画像を保存しません                 |
| JSONバックアップ                  | 全メタデータと画像のbase64文字列                             |
| Service Worker / Cache Storage    | 本番環境のアプリ表示用ファイル。初回の読み込み後にキャッシュ |

起動時にメタデータの形式・日付・参照先・画像の存在を検証します。壊れたデータが見つかった場合は既定データに戻して通知します。バックアップは形式・参照整合性と画像のデコードを検証してから復元します。復元前に現在の記録を置き換える確認を表示します。

サーバー保存・クラウド共有・外部API・画像の外部送信はありません。別の端末への移行はJSONバックアップで行います。ブラウザの保存領域の消去、容量制限、端末の故障に備えて定期的にバックアップしてください。同一ブラウザでは1つのタブで編集してください。Service Workerは本番のみ登録します。

## 注意

- 公的な電子小黒板の改ざん検知や、電子納品の正式フォーマットの要件には対応しません。
- 黒板入り画像は記録を読みやすくするための合成画像です。証明・認証機能はありません。
- 写真帳の画像表示が完了してから印刷してください。A4縦、倍率100%、ブラウザのヘッダー／フッターをオフに設定します。実際の余白やPDF保存方法はブラウザ・プリンターに依存します。
- ブラウザがデコードできない画像形式（環境によってはHEIC等）は、JPEG・PNG等に変換してから追加してください。
- バックアップの読み込みは250MBまでです。大量の写真は端末のメモリ・保存容量の制限を受けます。

## 技術スタック

Next.js 16（App Router）/ React 19 / TypeScript / Tailwind CSS 4対応環境 / CSS / Canvas API / IndexedDB / localStorage / Service Worker。外部Webフォントや外部画像、追加のnpmパッケージは使用していません。テストはNode.js標準のテストランナーで実行します。

`src/lib/` に日付・絞り込み・黒板・ページ割り・CSV・バックアップ検証などの純粋関数を配置し、canvas・IndexedDBへのアクセスを分離しています。

## ローカル起動方法

Node.js 24以上を使用します（テストでTypeScriptのネイティブ実行を利用）。このプロジェクトの直下で実行してください。

```bash
npm install
npm run dev
```

http://localhost:3000 を開きます。

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

本番起動はビルド成功後に実行してください。Prettierの整形幅は100です。

```bash
npx --yes prettier@3 --write "src/**/*.{ts,tsx,css}" "tests/**/*.js" README.md
```

## デモデータについて

会社「やまびこ工務店（架空）」、進行中2件・完了1件の計3工事、52枚のサンプル写真を初回に生成します。すべて架空の工事・住所・施工者で、実在の企業・個人とは無関係です。画像はcanvasで描画したサンプルで、隅に「サンプル画像」と表示します。基本は横長4:3で、縦長も含みます。

水回り改修は配管工・内装工、店舗外構は土工・基礎工・外構工が中心です。外壁改修は仮設工・下地補修・塗装工で構成します。未整理2枚、是正2枚、理由付きの掲載除外3枚を含みます。52枚の場所・工種・測点・区分・メモ・時刻は個別に記述し、工事ごとの撮影枚数は1日1〜6枚です。黒板は左下・中を基本に、接写などでは右下・右上・小を使用します。着工前写真は最初の撮影日、完了写真は工期末日に配置します。祝日は現行の規則で計算（春分・秋分は1980〜2099年の近似式）しており、将来の法改正には更新が必要です。撮影日は開いた日からの相対で、まとめて撮る日と撮らない日があります。「このデモについて」のリセット操作で、その時点の日付と画像を作り直せます。
